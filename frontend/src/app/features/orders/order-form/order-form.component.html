Lifecycle

What happens when you save

  1. NEW

    POST /api/orders validates the instrument through Feign, stores the order in PostgreSQL, and publishes an order-events Kafka message.

  2. SUBMITTED

    The screen immediately calls PATCH /api/orders/{id}/submit. The two calls stay explicit so the lifecycle is visible in the API and database.

  3. APPROVED or REJECTED

    An administrator decides from the order detail or list. A rejection requires a reason; both decisions are final.

  4. CANCELLED

    The requester (or an administrator) can cancel while the order is NEW or SUBMITTED. Approved and rejected orders are terminal.

Rules

Validation you can demonstrate

  • Instrument must exist and be active (Feign call to instrument-service).
  • Quantity and price must be positive, with at most 4 decimals.
  • Only an ADMIN can approve or reject; operations users own their orders.
  • If the instrument-service is down, creation fails with 503 instead of storing an unvalidated order.
